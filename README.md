# 115Rename Codex Version

用于115网盘**旧版文件页面**的 Tampermonkey（油猴）脚本。先预览清理与改名计划，核对后再执行，保留作品描述、个人备注及分集编号。

当前版本：**115Rename_CodexVersion_V2.4.8**。

[安装正式脚本](https://raw.githubusercontent.com/maxlixiang/115-/main/115Rename_CodexVersion.user.js) · [查看源码](./115Rename_CodexVersion.user.js)

## 安装与使用

1. 在浏览器中安装并启用 Tampermonkey。
2. 点击上方安装链接；也可以新建油猴脚本，完整粘贴仓库中的 `.user.js` 源码并保存。
3. 打开115**旧版**文件页面。右下角会显示“115 文件整理”入口，默认收起，每次刷新都不会自动展开。
4. 在115页面选中作品、人物或合集文件夹，点击右下角入口，再点“联网扫描并预览”。
5. 核对移动、删除和改名清单，可先下载“原名和预览”备份。
6. 点击“执行清理并改名”，确认弹窗后按计划执行。处理结束后保存结果和异常JSON，再刷新115查看。

更新时，建议在原脚本编辑页完整替换代码并保存，只保留一份正式脚本启用，避免多个版本同时运行。

### 新版115页面

目前不支持新版页面的文件选择结构。在新版打开插件，会显示“请先切回旧版”，并禁止扫描或执行。面板提供旧版入口及重新检测按钮；切换后重新选中文件夹再扫描。

## 执行前需要知道的清理规则

**这不是只改名的脚本。点击执行后，会先移动或删除预览中列出的内容。** 扫描、查看预览和下载备份本身不修改网盘文件。

|项目|行为|
|---|---|
|小文件|所选范围内所有类型的文件，严格小于 **200 MiB（209,715,200字节）** 时移入回收站；等于阈值的不因大小规则删除|
|作品内部子目录|连同剩余全部内容移入回收站，**不受200 MiB大小保护**|
|视频仅在内层|如果作品外层没有达到阈值的直接视频，先将内层达到阈值的视频移到直接外层，回读确认后再删除子目录及剩余内容|
|外层已有保留视频|按计划直接清理作品内部子目录，不额外搬出其中的其他视频|
|人物、合集和作品外层|不会因为包含子目录就将其本身删除；作品边界使用现有番号识别规则判断|
|大小未知、重名、内容变化|停止或跳过，不猜大小、不覆盖|
|失败或回读不一致|停止后续操作，记录已完成操作及异常；不会自动回滚，也不会自动重试结果不明的写操作|

删除只移入回收站，脚本不清空回收站。被删除小文件的名称不提取备注。**内层目录名称上的标签与备注不会自动继承**，需要保留时应事先整理到作品外层。

处理期间不要同时在其他页面移动、上传或重命名目标文件。执行前会重新检查目录内容，但远程操作无法形成完整的原子事务。

## 命名规则

### 作品文件夹

```text
发行日期_番号【描述】【备注：个人备注】 作品名称
```

例如：

```text
2024-01-01_ABC-123【2K】【中文字幕】【备注：舔脚1小时07，30分】 作品名称
```

- 联网查询顺序固定为 **javbus优先，avmoo备用**，不再提供下拉设置。保留已有备用站点逻辑。
- 查询结果必须匹配番号，并包含可用日期和作品名称；不能匹配时不猜资料。
- U、UC、uncensored等已支持标记转换为【无码】；C、CH转换为【中文字幕】。
- 支持2K、4K、HD、FHD等现有描述。`2K-C`及独立的旧备注`【备注：2K-C】`可转换为【2K】【中文字幕】。
- AI作为独立描述，不直接等同于无码。
- 时间备注、显式`【备注：…】`和“舔脚”等支持的备注保留到作品文件夹。
- 目标名按240个UTF-8字节控制。作品名过长时只截短作品名，描述和备注不截断；正常截短不进入待确认清单。
- 描述或备注自身过长、含不支持字符或目标重名时，保留原名并报告。

### 视频文件

```text
ABC-123.mp4
ABC-123-2.mp4
ABC-123-A.mkv
```

- 优先使用直接父作品目录的番号，不为每个视频单独联网查询。
- 去掉支持的来源前缀，统一大小写、横线和扩展名；数字位数按实际番号保留。
- 已识别的分集编号保留，同目录多版本需要区分时保留必要版本后缀。
- 番号明确、与父目录一致、无待转存备注或新标签的安全长标题视频，可先独立规范，再处理文件夹；其他视频仍先确认文件夹备注保存成功。
- SD、close、W、1080P、X1080X等已确认噪声按现有规则去除，遇到重名不会覆盖。

## 界面与进度

- 每次打开或刷新页面，默认显示右下角收起入口。
- 展开后使用固定尺寸、内部滚动的面板，状态行右侧显示已完成、总数和剩余任务数。
- 清理与改名分别计数，只有回读确认成功才计为完成。文件夹改名、视频改名各算一项操作。
- 收起不会停止正在运行的任务。需要停止时使用面板中的“停止”按钮；当前请求结束后停止后续操作。
- 界面使用 Shadow DOM 隔离115页面样式，并提供窄屏布局。

## 备份与异常报告

|下载文件|包含内容|
|---|---|
|原名与预览 / 改名前备份|原始目录、字节大小、清理计划、预期目录及改名计划|
|改名结果|执行日志、清理日志、成功/失败信息及快照|
|异常与待确认|只保留异常、待确认项与必要定位信息；不附带正常日志和完整目录快照；没有异常时不生成|

扫描完成后，即使不执行，也可点击“下载原名和预览”取得文件大小。`cleanup.originalItems`包含清理前文件名、路径及以字节表示的`size`。

备份用于核对和排障，并不代表脚本提供一键恢复功能。

## 当前限制

- 只支持115旧版页面，新版会提示切换。
- 没有新增FC2命名规则；需要保持原名的内容应单独核对。200 MiB小文件清理仍针对所选范围内的所有文件类型。
- 长标题末尾的`_1`、`_2`等分集可能无法识别，需先人工整理到番号附近，避免重名。不要强制覆盖或删掉分集。
- 未放进明确备注括号的未知自由文字，仍可能无法识别。重要备注建议预先使用`【备注：…】`。
- 联网结果受站点可用性、访问限制和页面结构影响。脚本不处理验证码、不保证每个番号都能查询成功。
- 默认保守检查重名；同名不等于内容重复，脚本不按文件内容或哈希自动去重。

## 数据与权限

脚本在浏览器中运行，通过115接口读取目录、文件大小并提交已确认的操作；通过现有资料站查询番号。备份JSON下载到本机，不会上传到本仓库，也没有额外的分析服务器。

`GM_xmlhttpRequest`的连接范围在脚本头部列出，包括115接口、javbus、avmoo及原有avsox备用域名。查询资料时发送番号；不要将包含网盘路径或其他个人信息的完整备份公开发布。

## 开发与验证

脚本无需打包，仓库根目录的`115Rename_CodexVersion.user.js`即安装文件。

使用Node.js 20及以上版本运行核心测试，无需安装依赖：

```sh
npm test
```

测试只使用合成文件数据，不连接真实网盘，不包含个人目录或备份。UI另外经过本地离线Chrome验证：默认收起、展开/收起、固定查询顺序及备用源、只读预览、新版提醒、清理失败停止、进度和窄屏布局。
